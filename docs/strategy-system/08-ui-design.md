# 页面设计、战报与原型范围

版本：SC-2.0-design · 2026-09-14。本文保留该日期的目标设计；当前实施进度及后续 UI 调整以 [正式迁移记录](12-production-migration.md) 为准。返回 [策略文档目录](README.md)。

## 13. 战报解释合同

每条记录固定六段：方向来源 → 有效证据 → 卡片影响 → 全局/状态影响 → 最终限制 → 决定及结算。

示例 A：装逼的人引用 CZ-02 本轮看涨订单 → 候选看空 → 价差过大 → 高手痒不解除限制 → 观望。

示例 B：占卜师三张牌给看涨 → EMA/盘口支持、ATR合格 → 谨慎版要求更多确认未达到 → 观望；不能把牌面重写成中立。

示例 C：疯狂凉兮短线候选看涨 → 强信号满足 → 全场上头提高合法全仓倾向 → 用户上限只有 50% → 选择半仓或观望，不把上限改成100%。

失败码至少包含 DATA_MISSING、DATA_STALE、WAIT_SIGNAL、WAIT_ORACLE、WAIT_CZ、PEERS_TIED、NO_PEERS、ASSET_UNSUPPORTED、COOLDOWN、STAKE_CAP、MINIMUM_STAKE、STOPPED、DEPENDENCY_TIMEOUT、MODEL_INVALID、STORAGE_FAILED。每个失败码都有中英文人话，不只给一串代码。

信号强度、模型自报把握、历史命中率分别命名。未经校准的百分数不能标为真实胜率。排行榜按明确净收益、相同资金规则与周期过滤；样本少时标记，娱乐称号不改分数。


## 14. UI 信息架构与视觉规范

页面：抽卡、卡册、人物详情/原版对比、阵容开局、战场、战报、战神榜。主导航以卡册和战場为常用入口，抽卡是强主操作；模型连接继续独立。

视觉沿用现有应用：顶部导航、原版骑电动车战神图标 `public/delivery-rider-scooter.png`、10U 字样与荧光黄倾斜的“战神”标牌、浅紫粉渐变背景、圆角描边和卡通底部阴影。主按钮使用原版荧光黄，卡面使用浅色底与紫色轮廓。样式依据 `anime.css`、`ui-v2.css`、`mobile.css`；原型适配集中在 `public/card-lab-brand.css`。卡片是完整人物肖像，不做装备格。KZG 使用用户照片参考版 `docs/images/kzg-mask-bro-avatar-v2.png`。

卡面正面：人物大图、人物名字、核心人设、最多三条词条、U/S/V三项数值。名称只显示人物名字，例如“火箭哥”，不拼接“狙击版”等变体类型；卡册、最近收藏和其他人物名称入口保持一致，中英文同步。细节放背面/详情，不把全部指标堆在缩略图上。角色颜色为辅助识别，不以颜色区分唯一状态。卡片顶部不显示“人物变体”或人物目录编号；当前原型不展示未定义的稀有度等级。

桌面沿用顶部品牌和导航，详情左右对比；平板将导航放在顶栏第二行；手机保留原版品牌图标与语言、底部主导航，抽卡单张居中，详情上下对照。新增策略功能保持原有品牌与组件风格，不替换成深色侧栏布局。触控主操作≥48px。360px 无横向溢出，英文长名可换行，弹窗有明确关闭和焦点管理。

抽卡动画约 0.6 秒，可跳过并尊重减少动画设置。加载/空/错误/已收藏/阵容满/依赖缺失等均有明确状态。不制造实时行情标记、假网络连接或伪造模型运行。


## 15. 可体验原型的交付范围

入口：`public/card-lab.html`。原型仅加载图片、静态目录和本地脚本，使用独立存储键，不复用真实对局数据。所有新增中英文文案集中于 `public/i18n.js` 的 CardLab 文案区。

交互：全人物随机抽完整卡、收藏、筛选卡册、打开详情、对比原版、加入/移出阵容、每实例模型绑定预览、开局配置预览、全局滑杆与下一轮预览、AI 决策分工及样例摘要、战报与榜单页切换。卡册展示全部 18 位原型供查看；抽卡页不提供人物池选择。

战场/战报/榜单使用明确标识的固定示例；不调用当前 server 的对局 API。收藏不声称服务端同步；浏览器存储失败时提示无法持久化。刷新保持已收藏卡、当前抽取结果、抽卡次数、恢复时间和语言，当前抽取不得自动变化。抽卡区显示“可抽次数 N / 5”和下一次恢复倒计时；次数不足时禁用抽卡按钮。卡册提供全部、已拥有、未拥有筛选，灰色未拥有卡可以查看原版，但不能收藏或加入阵容；新人物自动收藏；重复人物暂存供选择保留已有或确认覆盖，每个人物只保留一张。

UI 原型将收集审阅反馈后再接入正式路径。独立预览服务器只提供这些静态文件及既有头像，不启动交易、钱包或行情服务。



### 卡册布局审阅修订

卡册不提供搜索框。左侧为卡片类型，采用浅紫底、白色选中块的分段按钮；右侧为“全部 / 已拥有 / 未拥有”，采用轻量圆角筛选按钮与数量标记，并靠最右对齐。类型与拥有状态使用独立变量，可以组合筛选，右侧数量随类型更新。手机保持单行：左侧类型横滑，右侧拥有状态下拉选择。

卡册沿用原版小头像与摘要卡片比例：桌面宽屏 4 列，较窄桌面 3 列、平板 2 列，手机 1 列；头像桌面 60px、手机 52px。人物头像与名字并排，显示口头禅、词条、三项数值。整张卡片点击打开详情，取消“查看详情”文字按钮。页面主按钮为“选择阵容”，进入后才显示已拥有卡片右上角的勾选框；勾选即时保存，点击“完成选择”收起。筛选和语言切换保留选择模式，离开卡册或刷新后恢复浏览模式。未拥有卡与原型预览不能直接勾选。勾选不会触发详情弹窗，详情中仍可查看具体核心人设、大图和完整指标；主要触控区域至少 48px。


### 文案精简

抽卡页保留主标题、一句玩法说明、剩余次数和倒计时、人物资料与操作；删除重复口号、人物数量装饰、揭晓小标题和最近收藏副说明。全站删除装饰性栏目路径与页脚英文口号。保留必要的演示数据标识、AI 未接入、未拥有、依赖缺失、冷却、下一轮生效等状态，细节在人物详情和决策页查看。


### 属性刷新入口

已拥有卡片的详情底部只提供简洁的“刷新属性 · 1 次”操作按钮，不保留刷新说明区与“加入阵容”按钮；阵容在卡册的“选择阵容”模式统一勾选。重复人物抽取后的覆盖流程见 [属性刷新与重复卡覆盖](11-card-upgrades.md)。


### 战场沿用老版布局

战场参考 public/index.html、ui-v2.css、battle-controls.css 与 paper.css 的原有结构：顶部浅色对局控制栏，下方白底概览面板、全局状态条和人物战况。移除宣传式大标题及装饰折线。使用原品牌浅紫边框、卡通底部阴影、荧光黄主按钮。

桌面人物卡四列，平板两列，手机一列；小头像、口头禅、模拟净值、情绪数值、本轮示例与模型状态按层次排列。对局栏仅保留“开一局”按钮，点击打开开局设置弹窗；保留全局气氛和查看决策依据入口。概览净值为当前出场人物固定示例余额的合计，不能视为真实收益。全局状态条显示当前生效值，编辑仍通过原有全局设置弹窗，待下一轮生效。

### 开局设置弹窗

开局弹窗按“第一局、第二局……”自动编号，不提供名称输入。取消或 Escape 不递增，确认开打才保存编号；刷新继续计数，中英文按同一编号显示。

桌面左侧为已拥有角色的勾选卡片，右侧为币种、每轮时间、可输入和加减调整的每位本金（10 U / 100 U 为快捷选项）、轮次与实时进场。头像桌面 72px、手机 64px；手机纵向布局。最多选择 8 位，选择同步更新人数和总本金。空阵容、缺失 CZ 依赖及不支持币种仍会阻止开打。

表单使用独立草稿，关闭不修改已保存阵容和设置；切换语言保留草稿。开打后保存所选阵容，自动绑定唯一 CZ，保留人物卡与模型设置，并应用待生效全局设置，演示轮次从 1 开始。不运行行情、AI 或交易。

### 战神榜范围与战况详情

战神榜只保留最近一局、最近三局、全部三个范围，按各范围已结算净收益降序排列。榜单显示排名、头像名字、净收益与对局数，移除来源类别与条件等策略信息。点整行打开专属战绩弹窗，范围与当前榜单一致。

详情改为统计概览，不展示具体对局、轮次、单笔下注或输赢记录。核心指标为净盈利、下注次数、范围内胜率、综合胜率；补充胜负分布、累计下注额、含本金返还、下注收益率、平均下注额、累计盈利和累计亏损。详情不包含性格、指标、模型或策略说明。

范围内胜率按当前最近一局/最近三局/全部的获胜下注数除以已结算下注数；综合胜率始终按全部历史汇总，不平均各局百分比。收益率为净盈利除以累计下注额。累计盈利减累计亏损、累计返还减累计下注额均等于净盈利。

数据是 6 位人物、5 局已结算的固定汇总示例，并明确标记非真实战绩。使用整数分保存金额，下注数量与胜负分布为固定演示数据。未接入真实历史；新增开局或抽卡不会伪造已结算记录，未新增交易调用或存档字段。

scripts/verify-card-ranking.cjs 验证三种范围重新排序、18 组人物/范围的次数和资金统计关系、综合胜率不随筛选变化、详情无逐轮记录及策略信息、键盘访问与四种语言的 1301/768/360px 布局。截图在 artifacts/card-lab/ranking-summary-*.png。

### 战场顶部实时行情与对局标题

顶部左侧沿用原版现货参考价结构：当前币种/USDT、最新成交价、行情状态和更新时间。对局编号（或原有自定义名称）移入下方主卡片标题，替换对局概览，币种与周期保留在标题下。模拟战况与实时行情分别标注。
