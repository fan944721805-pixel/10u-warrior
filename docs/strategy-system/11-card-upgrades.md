# 属性刷新与重复卡覆盖

COL-1 已接入新版页面、正式 HTTP 服务和 Android 共用运行时。卡片与次数由服务保存，浏览器只保存界面偏好、旧数据备份和未确认请求。抽卡流程不调用模型、钱包或交易接口。

## 刷新属性

已拥有卡片的详情底部显示“刷新属性 · 1 次”。原型图鉴和未拥有卡片没有刷新入口，也不能通过“收藏”获得免费卡片。阵容在卡册勾选。

刷新和抽卡共用初始 5 次、每 10 分钟恢复 1 次、最多 5 次的额度。服务选择随机种子，刷新仅改变手痒、情绪敏感、变化三项数值和卡片修订号；数值可升可降，限制在人物范围内。人物、风格、词条、指标、卡片 ID、收藏时间和界面中的模型绑定保持不变。

卡片变更与扣次数在同一个原子文件提交，保存失败不报告成功。服务恢复额度使用服务时钟；页面倒计时以服务时间加单调经过时间显示，不根据浏览器时钟自行增加额度。零次时抽卡页、详情和开局弹窗的去抽卡入口均显示冷却并禁用，服务确认恢复后才重新启用。

## 重复人物卡

每个人物仅保留一张已拥有卡。首次获得人物自动收藏；重复结果保存在服务的 pending 字段，不计入已拥有数量或出场阵容。

抽卡页对比唯一已有卡。“保留已有”丢弃暂存结果；“确认覆盖”把新结果写到已有卡的 ID 上，沿用收藏时间、阵容引用和模型绑定并增加修订号。两种操作都不额外扣次数。关闭弹窗不丢弃结果，重载后仍可处理；再次抽卡会用本次结果替代上一份暂存结果。

客户端携带集合版本、目标卡修订号与暂存卡 ID。另一客户端先改动时，旧确认被拒绝，刷新后重新查看对比。历史对局保存的是冻结副本，收藏刷新和覆盖不改写已开对局。

## 迁移与恢复

首次连接新服务前，页面备份旧 warrior-single-card-concept-v2 及其 -draws 原始字符串，保存为 -service-backup。已有卡 ID、数值与待确认重复卡保持不变。旧数据如含同人物多张卡，优先保留阵容排名靠前者，否则保留较新的收藏；完整原始集合仍在备份中。

旧集合只可导入尚未使用的服务收藏。相同导入重复发送不会再扣次数或覆盖后来变更；服务已有不同收藏、源数据损坏或校验失败时停止自动导入，保留备份并显示提示。用户可明确选择使用服务收藏，原始本地数据仍保留。不会静默把冲突集合清空。

每次变更先保存独立的请求恢复记录，再发送幂等编号。响应丢失后重试同一编号，不重新抽取或扣次。多个标签页不会覆盖彼此未确认的记录；重新打开页面能发现并重试未确认请求。集合版本冲突是确定拒绝，刷新后再操作。损坏的恢复记录禁止继续抽取，避免把不确定操作当作未发生。

界面偏好改存 -preferences-v1，不再合并并写回旧收藏。新版开局携带 collectionRevision；服务核对该版本、拥有的卡 ID 和快照，防止使用刚被刷新或覆盖的旧选择。既有创建请求仍优先按幂等编号恢复。

## 存储与验证

服务数据为 .data/card-collection.json，原生路径为 /mobile/data/card-collection.json，均复用项目原子存储适配。模块面向单个应用服务拥有存储、多客户端访问的部署，不提供多主进程写入或跨设备账户同步。旧本地数据导入是兼容迁移，不是对其抽卡来源的防作弊证明。

- test/card-collection.test.cjs：额度、服务时间、原子保存、生成失败、重载、幂等、版本冲突、导入与选择校验。
- test/card-collection-client.test.cjs：原始备份、断线恢复、独立请求记录、多客户端恢复、损坏状态、导入冲突与单调倒计时。
- scripts/verify-card-collection-service.cjs：正式 HTTP 页面上的新用户、旧集合迁移、刷新属性、覆盖/放弃、请求结果丢失、冷却和四语言三尺寸。
- scripts/verify-card-collection.cjs：19 人物图鉴、筛选、禁止通过图鉴获得卡片、阵容选择持久化与图片加载。
- scripts/verify-card-upgrades.cjs 复用正式收藏交互验证，不再断言本地扣次逻辑；verify-card-lab.cjs 汇总当前服务交互和本地化检查。

这些是隔离服务与浏览器验证，未调用用户模型或钱包，也不代表 Android 真机或真实交易验证。
