## AI 决策参与

### 10.1 AI 是决策参与者，程序是事实与约束执行者

同一人物卡可在不同对局绑定不同模型，卡片本身不绑定品牌，不把 GPT/Claude/DeepSeek 当作可抽取的性格。每个阵容实例保存 connectionId、connectionRevision、modelId、决策模式和预算。沿用现有 ai-connections、ai-routing、ai-decision，不新建重复连接系统。

| 决策步骤 | AI 的职责 | 程序的职责 |
| --- | --- | --- |
| 行情理解 | 判断趋势、震荡、突破可靠性与信号矛盾 | 计算指标、提供时效和原始事实，不让模型编数 |
| 技术人物方向 | 在人物方法允许范围内权衡证据，选择看涨、看空或观望 | 资产、人设、数据、硬风险限制；核对所引用证据 |
| 占卜人物 | 解读已冻结牌面/卦象，并权衡行情是否值得执行 | 原始占卜方向不可改，中立不可自行找方向 |
| 反押人物 | 评估目标行为和反向机会，决定执行或等待 | 确保目标合法、当轮有效、反向来源不被替换 |
| 性格与情绪 | 按词条和有效数值体现耐心、激进、胜负反应 | 计算实际状态增量与时限，防止无限加码 |
| 金额选择 | 在合法金额/档位里选择本轮投入，或认为不足以承担风险而观望 | 精确金额、余额、总暴露、上限和最低额校验 |
| 解释 | 输出简洁决策摘要、关键证据、冲突点与不确定性 | 保存摘要和证据 ID；不索取或展示隐式思维链 |

技术人物的本地规则要拆成“硬约束”与“方法参考”。硬约束包括资产方向、最低证据存在、人物不可变方法、来源时效和硬风险阈值；方法参考包括指标一致性、结构强弱、默认参与阈值。模型可以在参考项冲突时做权衡，不能突破硬约束。第 7 节 KZG 阈值定义默认识别特征与强信号状态条件，不等于本地已经确定最终下注；AI 仍须评估结构是否可靠、矛盾是否值得承担，并可选择观望。真正作为阻断条件的项在执行配置中显式标记为 hard，不因模型一句话临时改变。

对“装逼的人”，反向候选固定，AI 可以认为风险不值得而放弃，不能改成跟 CZ。逆行者首版保持程序产出的合法目标/权重事实，AI 解释其意义并决定反押或等待；后续如开放权重调整，须在有界字段中回传并由程序重算，不允许只写一句“我觉得另一边更差”就改来源。

### 10.2 输入、输出与模型故障

每轮输入五块：人物卡与不可变规则、指标/赔率/时效、个人资金/已结算历史、有效情绪与全局版本、合法目标或冻结占卜。附结构化数据引用 ID 和可用动作/金额范围；不提供 API 密钥、不让模型自己请求付款或调用交易工具。

结构化输出至少包含 roundId、snapshotId、action、direction、stakeChoice/amount、evidenceIds、counterEvidenceIds、uncertainty、summary、personaEffectSummary。模型自报 confidence 可保存但单独标注，不能被描述为真实胜率，也不能单凭高自报值解锁梭哈。

程序校验 schema、引用事实、人物方向来源、模型配置版本、金额以及本轮时限；不合法则拒绝并记录原因，不能自动反向执行。可以在剩余时限和预算内进行最多一次结构修复请求；无可用结果则本轮观望，冻结种子和数据版本不变。

AI 故障默认观望，并显示原因。用户可在开局选择“故障时使用本地规则”，每次降级必须标记引擎和原因；不能不告知用户就把本地结果说成 AI 判断。原型的模型选择仅演示绑定交互，所有选项都标为待接入，不伪装连接成功。

调用预算按每实例每轮最多一次正常决策+一次可选修复，设对局 token/费用上限和超时。费用未知时显示未知，实际记录供应商返回 usage；超预算停止新增 AI 请求。实时调用不可通过多抽几次结果挑有利输出，卡片随机也不得触发付费模型调用。

### 10.3 如何证明 AI 确实参与

未来接入必须使用同一冻结行情和卡片测试：模型选择观望时程序不能替它下注；技术信号冲突时不同有效输出能改变最终行动；固定来源人物不能逆转来源；无效输出被拒绝；每笔记录能追踪实际 provider/model、输入版本和输出。测试只证明调用与权限边界，不证明收益提升。

UI 必须有模型绑定、分析中/超时/本地降级状态、指标依据/反向证据/卡片影响三类摘要。示例分析明确标“演示摘要，未调用模型”，不能把预制台词冒充实时 AI 结果。
