## 18. 实施分期与审阅顺序

第一阶段（本次）：完成本文、可操作 UI 原型、浏览器多端验证与截图；让用户看见单卡系统最终方向。

第二阶段：人物约束、风格与词条目录、变体生成器、版本与状态计算。逐方案接入指标，先通过固定快照测试。

第三阶段：接入现有模拟决策、分阶段依赖、账本、持久化和预计算；验证资金与占卜的版本差异。

第四阶段：替换正式 UI 入口、完成旧版迁移与 Android/小组件回归。上线范围明确，不把设计原型自动打包为正式交易功能。

审阅重点：单卡视觉是否符合预期；人物变体是否有个性但不变人设；卡面信息是否足够直白；全局气氛能否看出对每张卡的影响。参数可在此规格版本内继续修订，但任何修改都保留来源和状态边界。

## 19. 本次交付与实测结果

2026-09-14 完成十份主题规格与本目录索引。已提供独立的可操作 UI 原型，未接入正式策略执行、真实 AI 请求或真实交易。

同日按审阅反馈恢复原有品牌：复用骑电动车战神图标，恢复顶部导航、浅紫粉背景、荧光黄按钮与圆角卡通阴影。人物卡及其他新增页面统一沿用该风格；交互、收藏和阵容数据保持原有逻辑。修改后重新通过下列页面与交互检查。

- 预览地址：[右侧浏览器预览](http://127.0.0.1:4188/card-lab.html)。启动命令：在项目根目录运行 `node scripts/serve-card-lab.cjs`；默认端口 4188。
- 页面：抽卡、卡册、阵容、战场、AI 决策、战报、榜单。可抽取并保存完整人物卡、查看原版对比、配置阵容和模型、预览下一轮全局设置。
- 浏览器自动验证通过：7 页 × 中英文 × 360/768/1440 三种宽度，共 42 组页面检查，另有 12 组弹窗截图。无横向溢出、缺图和浏览器错误；主要操作按钮高度满足 48px 要求。
- 交互验证通过：18 位人物目录、全人物随机抽取（无人物池选择）、刷新保留同一卡片、重复收藏不增副本、人物详情、阵容模型绑定、CZ 依赖绑定、资产限制、全局设置下一轮生效、基础属性不变、自定义对局名不翻译。
- 网络验证：页面只读取本地静态资源，无 AI 或交易 API 请求。预览服务器拒绝写入请求和未允许的文件路径。

验证脚本为 `scripts/verify-card-lab.cjs`，需要 Playwright 与 Chrome；可通过环境变量 `PLAYWRIGHT_PATH` 指定已安装的 Playwright 模块。机器可读结果见 [verification.json](../../artifacts/card-lab/verification.json)。

## 20. 卡册收集与抽卡次数补充验收

2026-09-14：原型新增未拥有人物、已拥有/未拥有筛选和自动收藏；初始 5 次，每 10 分钟恢复 1 次，上限 5 次。现有收藏与阵容保留，旧预览首次启用次数系统时获得 5 次。

- `node --test test/card-lab-draws.test.cjs`：5 项时钟边界测试通过，覆盖耗尽、十分钟前一毫秒、恰好十分钟、离线恢复、上限、满额后重新计时、刷新与时钟回退。
- `scripts/verify-card-collection.cjs`：验证未拥有卡不可直接获得、抽后自动解锁、五次耗尽后禁用、刷新保留、定时恢复、中英文提示、两个标签页同时争取最后一次机会时只成功一次。浏览器使用虚拟时钟推进十分钟，没有依赖真实等待。
- 结果见 [collection-verification.json](../../artifacts/card-lab/collection-verification.json)；截图见 [卡册收集状态](../../artifacts/card-lab/collection-owned-1301-zh.png)、[次数与冷却](../../artifacts/card-lab/draw-cooldown-1301-zh.png)。
